# Albums Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let each member group their own photos and videos into named, many-to-many "collection" albums, on web and mobile.

**Architecture:** Two new tables (`album`, `album_media`). `GET /api/media` and `GET /api/media/timeline` gain an optional `albumId` filter, so an album view is the existing gallery (headings, rail, paging window) scoped to one album. Album CRUD and add/remove endpoints are new. Each client gains an album list, an album screen, a select mode, and an album picker.

**Tech Stack:** Next.js App Router + drizzle (Postgres), Zod in `packages/shared`, Expo/expo-router, vitest (added to `packages/shared` only, for pure helpers).

**Spec:** `docs/superpowers/specs/2026-11-22-albums-design.md`

## Global Constraints

- Albums are personal: every album query is scoped to the caller; a non-owned or missing album is **404**.
- Album name: trimmed, 1–100 characters; duplicate names allowed.
- Add/remove take at most **200** `mediaIds` per request; clients chunk larger selections into sequential calls of 200.
- Add requires every id to be a `ready` media row owned by the caller, else **400** and nothing is added. Add and remove are idempotent. "New album" with `mediaIds` is one transaction.
- Removing from an album and deleting an album never delete a `media` row or call `deleteObjects`. Photo delete stays the existing permanent delete with its existing confirmation.
- Album `count` counts only `ready` media; cover = thumbnail of the newest ready item by `(takenAt, id)`; `GET /api/albums` is ordered `updatedAt desc`. `updatedAt` bumps on rename and on add/remove through album endpoints only.
- No upload-into-album, no reordering, no custom cover, no sharing.
- Styling follows each app's `DESIGN.md` (web tokens in `globals.css`; mobile `src/theme.ts`). Chrome stays quiet: select mode UI appears only once entered, and always has a visible exit.
- Implement on a fresh branch from up-to-date `origin/main` (the timeline is merged there); not from `feat/gallery-timeline`.

## Review Focus

1. Another member's `albumId` on any route (get, patch, delete, add, remove, `GET /api/media?albumId`, `/timeline?albumId`) → 404, never data. (Tasks 3, 4)
2. `mediaIds` containing another member's id, a `pending` id, an unknown id, or duplicates → 400 for foreign/pending/unknown with nothing added; duplicates collapse. (Task 3)
3. Deleting a photo that is in albums drops it from every album and from counts and covers (cascade). (Task 3)
4. Deleting an album leaves every photo and S3 object intact. (Task 3)
5. Names that are blank, whitespace-only or 101 characters; empty `mediaIds`; 201+ ids; an emptied album (stays, count 0, cover null). (Tasks 1, 3, 8)
